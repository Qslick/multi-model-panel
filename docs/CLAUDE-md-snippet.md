# Routing rules for `~/.claude/CLAUDE.md`

Skills trigger on their descriptions, but the "propose the panel before and after heavy work" habit holds best when it is also written in your global `CLAUDE.md`. Paste the block below into `~/.claude/CLAUDE.md` and edit to taste.

```markdown
- **Cross-model review runs through one skill family.** `/multi-model-panel` (alias `/panel`) convenes four read-only seats from four model families: Codex, Gemini via `agy`, Grok via the `grok` CLI, and a fresh-context Claude on a different model than the convener. All four get one identical packet and answer independently; the convener synthesizes and rules with seat attribution. A seat whose provider is out of usage is benched for the rest of the session and the panel runs on the remaining seats. `/claudex-loop` is the full four-phase run (recon, interview, adversarial Codex review, optional build); `/codex-review` is the single-critic Codex loop that iterates a `PLAN.md` to APPROVED; `/codex-build` hands a frozen `PLAN.md` to Codex to implement.
- **Default to `/multi-model-panel` on heavy or precise work: propose it, don't wait to be asked, before AND after.** Before committing to anything architectural, multi-file, security- or data-sensitive, hard to reverse, or otherwise expensive to get wrong (auth, schema/migrations, concurrency, payments, greenfield architecture, public API shape, deletes, deploys), stop and offer the panel; after completing such work, run it as a completion check before declaring done. One line is enough, then respect the answer. Skip the offer silently for single-file mechanical edits, typo/config tweaks, and work already verified.
- **The Codex side reads `~/.codex/config.toml`: never pin `-m`.** The skills read `model` from config.toml at run time; effort is passed per run with `-c model_reasoning_effort=…`. The panel's Gemini and Grok model ids, the Codex and Grok efforts, and the Claude agent names live in `~/.claude/skills/multi-model-panel/roster.json`; the Claude seat's model and effort live in `~/.claude/agents/panel-claude-{fable,opus}.md`.
- **`/codex-build` is the unsandboxed one, and the proactive-offer rule does NOT extend to it.** It runs Codex with full write access and no approval prompts, so invoke it only on explicit request. The other skills keep Codex strictly read-only.
```
